### CU-05 · Registrar auditoría

| **Módulo · Prioridad** | M04 · Auditoría y Trazabilidad · Prioridad Crítica · Etapa 1 y 3 |
| --- | --- |
| **Actor primario** | Sistema (invocado por otros casos de uso) |
| **Actores secundarios** | — |
| **Requisitos** | RF-05, RN-02, RNF-13 |
| **Descripción** | Registra de forma protegida los eventos críticos de seguridad, administración, inspección, asignación de recursos, donaciones y cambios de modo. Es un caso de apoyo, sin interacción directa de un actor. |
| **Precondiciones** | Ocurre un evento crítico en otro caso de uso (por ejemplo, CU-04, CU-08, CU-36, CU-42 o CU-43). |
| **Disparador** | El caso de uso invocante notifica un evento crítico. |
| **Flujo principal** | **1.** El sistema recibe el evento con su contexto.  **2.** El sistema reúne: actor, fecha y hora, acción, recurso afectado y resultado; y estado anterior y nuevo cuando aplica.  **3.** El sistema escribe el registro en un almacén protegido contra modificación y borrado por usuarios operativos.  **4.** El sistema confirma el registro al caso invocante. |
| **Flujos alternativos** | **A1** Evento originado sin conexión: se registra con la marca de tiempo original y la de sincronización (CU-37). |
| **Excepciones** | **E1** No se puede escribir el registro: la operación crítica invocante no se completa y se genera una alerta operativa (RNF-13).  **E2** Evento con datos incompletos: el sistema lo rechaza y lo reporta como error de integración. |
| **Postcondiciones** | Existe un registro completo e inalterable del evento. |
| **Reglas de negocio** | Los usuarios operativos no pueden alterar los registros de auditoría (RF-05). Los registros no se eliminan por cambios de modo (RN-02). No hay acción crítica sin traza. |
| **Relaciones** | «include» desde CU-04, CU-08, CU-36, CU-42 y CU-43. Se consulta mediante CU-09. |
| **Criterios de aceptación** | Una acción crítica genera un registro con actor, fecha y hora, acción, recurso y resultado que el usuario operativo no puede modificar. |
