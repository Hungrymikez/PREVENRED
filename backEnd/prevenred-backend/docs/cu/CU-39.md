### CU-39 · Gestionar incidentes

| **Módulo · Prioridad** | M09 · Reporte de Incidentes y Solicitudes de Ayuda · Prioridad Crítica · Etapa 3 |
| --- | --- |
| **Actor primario** | Administrador |
| **Actores secundarios** | — |
| **Requisitos** | RF-24, RF-22, RF-05, RN-04 |
| **Descripción** | Permite al coordinador revisar, asignar y hacer seguimiento a los incidentes por el ciclo Reportado → En revisión → Asignado → En atención → Resuelto/Despejado, con fecha y responsable de cada transición. |
| **Precondiciones** | El Modo Emergencia está activo. Existen incidentes reportados (CU-29, CU-30 o CU-31). |
| **Disparador** | El administrador abre «Incidentes» en el dashboard. |
| **Flujo principal** | **1.** El sistema lista los incidentes con filtros por estado, tipo, comuna o barrio y fecha.  **2.** El administrador abre un incidente y revisa la descripción, la evidencia y la ubicación en el mapa.  **3.** El administrador revisa los posibles duplicados marcados por el sistema.  **4.** El administrador pasa el incidente a «En revisión» y lo valida.  **5.** El administrador asigna el incidente a un inspector, técnico o voluntario; el estado pasa a «Asignado».  **6.** El sistema registra la asignación en auditoría y notifica al asignado y al ciudadano (CU-06).  **7.** Durante la atención, el estado pasa a «En atención».  **8.** Al concluir, el administrador marca el caso como «Resuelto/Despejado». |
| **Flujos alternativos** | **A1** Incidente duplicado: el administrador lo vincula al caso principal.  **A2** Asignación de una inspección: genera la asignación consultable en CU-38 y el inicio de CU-34 y CU-36.  **A3** Transición no permitida: el sistema solo admite los cambios válidos del ciclo de vida (ver observación O-11). |
| **Excepciones** | **E1** La persona asignada no está disponible: el sistema pide elegir otra.  **E2** Otro administrador modificó el incidente: el sistema informa y recarga los datos.  **E3** Falla el registro de auditoría de la asignación: la asignación no se confirma. |
| **Postcondiciones** | Cada transición queda registrada con fecha y responsable. El ciudadano fue notificado del cambio de estado. |
| **Reglas de negocio** | Cada cambio de estado queda en la auditoría y se notifica al ciudadano. La asignación se modeló como acción del Administrador; queda pendiente si será automática o aprobada (ver observación O-10). |
| **Relaciones** | Gestiona lo creado en CU-29, CU-30 y CU-31. Se apoya en CU-40 y CU-06. Genera tareas para CU-38, CU-34 y CU-43. |
| **Criterios de aceptación** | Un incidente avanza por los cinco estados, con fecha y responsable en cada transición, y el ciudadano recibe las notificaciones. |
