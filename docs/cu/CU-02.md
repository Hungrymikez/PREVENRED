### CU-02 · Iniciar sesión

| **Módulo · Prioridad** | M01 · Acceso, Usuarios y Roles · Prioridad Crítica · Etapa 1 |
| --- | --- |
| **Actor primario** | Ciudadano; Técnico / Voluntario; Inspector; Administrador |
| **Actores secundarios** | — |
| **Requisitos** | RF-03, RF-02, RNF-06, RNF-14, RN-07 |
| **Descripción** | Autentica al usuario y abre una sesión de duración limitada. El rol y el modo operacional vigente determinan los menús y funciones que se le presentan. Para cuentas administrativas se extiende con CU-03 (segundo factor). |
| **Precondiciones** | El usuario tiene una cuenta activa (CU-01 o creada por un Administrador en CU-08). Existe conectividad para el primer inicio de sesión. |
| **Disparador** | El usuario abre la aplicación o el dashboard sin sesión vigente. |
| **Flujo principal** | **1.** El usuario ingresa sus credenciales.  **2.** El sistema valida las credenciales y el estado de la cuenta (activa).  **3.** El sistema identifica el rol del usuario; si es una cuenta administrativa, se ejecuta CU-03 antes de continuar.  **4.** El sistema emite una sesión o token de duración limitada, con rotación o revocación cuando corresponda.  **5.** El sistema consulta el modo operacional vigente (Cotidiano o Emergencia).  **6.** El sistema presenta el inicio con los menús, accesos y flujos autorizados para el rol y el modo. |
| **Flujos alternativos** | **A1** Cuenta administrativa: el sistema exige el segundo factor (CU-03); sin él no se emite la sesión.  **A2** Recuperar acceso: el usuario solicita la recuperación; el sistema envía un mecanismo de restablecimiento al medio de contacto registrado y permite definir nuevas credenciales.  **A3** Sesión vencida: el sistema pide autenticarse de nuevo; si hay datos pendientes de sincronizar (CU-37), se conservan.  **A4** Cerrar sesión: el usuario finaliza la sesión y el sistema revoca el token. |
| **Excepciones** | **E1** Credenciales inválidas: el sistema muestra un mensaje genérico que no revela cuál dato falló.  **E2** Intentos repetidos fallidos: el sistema bloquea temporalmente el acceso (RNF-14).  **E3** Cuenta suspendida o desactivada: el sistema niega el acceso e indica cómo contactar a la entidad.  **E4** Sin conectividad y sin sesión vigente: no es posible iniciar sesión; con sesión vigente siguen disponibles las funciones de campo sin conexión. |
| **Postcondiciones** | Sesión activa con rol y modo operacional cargados. Los accesos de cuentas administrativas quedan registrados (CU-05). |
| **Reglas de negocio** | RN-07: las cuentas administrativas aplican mínimo privilegio y MFA. La duración y renovación de la sesión se definen en la arquitectura (documento 07). |
| **Relaciones** | «extend» CU-03 si la cuenta es administrativa. Es la puerta de entrada a todos los demás casos de uso. |
| **Criterios de aceptación** | Un usuario con credenciales válidas accede solo a las funciones de su rol y del modo vigente. Un administrador no obtiene sesión sin completar el segundo factor. |
