### CU-07 · Recibir notificaciones de crisis

| **Módulo · Prioridad** | M03 · Notificaciones y Alertas · Prioridad Crítica · Etapa 3 |
| --- | --- |
| **Actor primario** | Ciudadano; Técnico / Voluntario; Inspector |
| **Actores secundarios** | Servicio Push/SMS |
| **Requisitos** | RF-04, RF-24 |
| **Descripción** | El usuario recibe en su dispositivo las alertas de emergencia de su zona, así como los avisos sobre sus casos o sus asignaciones. |
| **Precondiciones** | El usuario tiene cuenta activa y su zona está incluida en el envío. El usuario no ha excluido este tipo de aviso, salvo excepciones legales. |
| **Disparador** | El sistema entrega una notificación al dispositivo (Push) o al número registrado (SMS). |
| **Flujo principal** | **1.** El dispositivo recibe la notificación.  **2.** El usuario la visualiza.  **3.** El usuario abre la notificación.  **4.** La aplicación consulta el modo operacional vigente y muestra la pantalla de Modo Emergencia o el detalle del caso o asignación.  **5.** El sistema marca la notificación como leída. |
| **Flujos alternativos** | **A1** El usuario recibe un SMS por no tener la aplicación activa: el mensaje incluye la instrucción esencial de la autoridad.  **A2** El usuario administra sus preferencias de notificación dentro de las excepciones legales aplicables. |
| **Excepciones** | **E1** Sin conectividad de datos: el Push no llega; al reconectar, la aplicación consulta el estado vigente.  **E2** Permisos de notificación desactivados en el dispositivo: la aplicación lo advierte al abrirse. |
| **Postcondiciones** | El usuario conoce la alerta y accede al modo y a las funciones habilitadas. |
| **Reglas de negocio** | Las notificaciones respetan las preferencias del usuario y las excepciones legales. |
| **Relaciones** | Recibe lo emitido por CU-06. |
| **Criterios de aceptación** | Un usuario de una zona notificada recibe el aviso y, al abrirlo, ve únicamente las funciones permitidas para su rol. |
