### CU-10 · Configurar catálogos y capas de mapa

| **Módulo · Prioridad** | M10 y M11 · Censo de Inmuebles e Inspección / Mapa Multicapa · Prioridad Crítica · Etapa 3 |
| --- | --- |
| **Actor primario** | Administrador |
| **Actores secundarios** | — |
| **Requisitos** | RF-20, RF-25, RN-04 |
| **Descripción** | Mantiene el catálogo oficial de niveles de daño y las capas del mapa (reportes, zonas de riesgo, infraestructura crítica, red vial y bienestar por barrio), con visibilidad por rol, versionado y fecha de actualización. |
| **Precondiciones** | El administrador tiene sesión vigente y permiso de configuración. La autoridad competente suministró el protocolo, el catálogo o los datos de la capa; en su ausencia, se usan datos de prueba marcados como tales. |
| **Disparador** | El administrador abre la configuración de catálogos y capas. |
| **Flujo principal** | **1.** El administrador elige trabajar con el catálogo de niveles de daño o con una capa del mapa.  **2.** Catálogo: crea o edita niveles con su etiqueta y descripción, según el protocolo oficial. Capa: carga o actualiza los datos geoespaciales y define nombre, fuente, responsable de la fuente y fecha de actualización.  **3.** El administrador define la visibilidad por rol (capas) y la fuente o protocolo oficial que respalda el cambio.  **4.** El sistema valida la estructura (campos obligatorios, geometrías válidas, sin etiquetas duplicadas).  **5.** El sistema guarda una nueva versión sin sobrescribir la anterior.  **6.** El sistema aplica la versión vigente a nuevas capturas y muestra la fecha de actualización. |
| **Flujos alternativos** | **A1** Carga con datos de prueba: el sistema identifica el catálogo o la capa como «datos de prueba» hasta recibir los oficiales.  **A2** Desactivar un nivel o capa: se marca como inactivo; no se elimina el historial. |
| **Excepciones** | **E1** Archivo geoespacial inválido: el sistema lo rechaza e indica el error.  **E2** Etiqueta duplicada o incompleta: el sistema no guarda el cambio.  **E3** Usuario sin permiso: el sistema niega la acción. |
| **Postcondiciones** | Existe una versión vigente del catálogo o la capa, con trazabilidad de fuente y fecha. Los registros ya capturados conservan la versión con la que se clasificaron. |
| **Reglas de negocio** | Las etiquetas de daño las define y valida la autoridad competente; el sistema no decide por sí solo (RN-04). La información cartográfica depende de los catálogos oficiales de las entidades. |
| **Relaciones** | Alimenta a CU-35 (catálogo de daños) y CU-40 (capas). |
| **Criterios de aceptación** | Un cambio en el catálogo queda versionado y CU-35 solo permite elegir niveles del catálogo vigente. Una capa puede activarse o desactivarse y muestra su fecha de actualización y responsable. |
