### CU-16 · Moderar contenido y reseñas

| **Módulo · Prioridad** | M06 y M07 · SegundaVida Pereira / OficiosYa Pereira · Prioridad Media · Etapa 2 |
| --- | --- |
| **Actor primario** | Administrador |
| **Actores secundarios** | — |
| **Requisitos** | RF-09, RF-12, RN-06 |
| **Descripción** | Permite aplicar controles contra el abuso y el contenido inapropiado en publicaciones, reseñas y evidencias (fotos y videos de cotización). |
| **Precondiciones** | El administrador tiene sesión vigente y permiso de moderación. Hay elementos reportados por usuarios o marcados por controles automáticos básicos. |
| **Disparador** | El administrador abre la cola de moderación. |
| **Flujo principal** | **1.** El sistema lista los elementos pendientes con motivo del reporte.  **2.** El administrador abre un elemento y revisa el contenido y su contexto.  **3.** El administrador decide: mantener, ocultar o eliminar el contenido, o advertir o suspender al autor.  **4.** El administrador registra el motivo de la decisión.  **5.** El sistema aplica la decisión y notifica al autor.  **6.** El sistema cierra el caso de moderación. |
| **Flujos alternativos** | **A1** Si la decisión es suspender a un técnico, el sistema actualiza su estado de verificación a «Suspendido» (CU-18, A2).  **A2** El administrador desestima el reporte: el contenido se mantiene visible. |
| **Excepciones** | **E1** El contenido ya fue retirado por su autor: el sistema cierra el reporte.  **E2** Otro administrador resolvió el elemento: el sistema informa y recarga la cola. |
| **Postcondiciones** | El contenido queda visible, oculto o eliminado según la decisión, con el motivo registrado. |
| **Reglas de negocio** | Las evidencias de cotización se tratan con controles de acceso y retención (RN-06). La moderación es básica en la v1.0. |
| **Relaciones** | Recibe reportes originados en CU-11, CU-15 y CU-20. |
| **Criterios de aceptación** | Un administrador oculta una reseña reportada y el autor recibe la notificación con el motivo. |
