### CU-18 · Verificar técnico

| **Módulo · Prioridad** | M01 y M07 · Acceso, Usuarios y Roles / OficiosYa Pereira · Prioridad Alta · Etapa 2 |
| --- | --- |
| **Actor primario** | Administrador |
| **Actores secundarios** | — |
| **Requisitos** | RF-10, RF-05, RN-07 |
| **Descripción** | Permite al administrador administrar el estado de verificación de los técnicos: Pendiente, Verificado, Rechazado o Suspendido. |
| **Precondiciones** | El administrador tiene sesión vigente, autenticada con segundo factor. Hay perfiles de técnico pendientes de revisión. |
| **Disparador** | El administrador abre la cola de técnicos pendientes. |
| **Flujo principal** | **1.** El sistema lista los perfiles pendientes.  **2.** El administrador abre un perfil y revisa identidad, especialidad, experiencia y documentos.  **3.** El administrador decide verificar o rechazar.  **4.** En el rechazo, el administrador indica el motivo.  **5.** El sistema actualiza el estado, notifica al técnico y registra el evento en auditoría.  **6.** Si fue verificado, el perfil aparece en OficiosYa con la insignia «Verificado». |
| **Flujos alternativos** | **A1** Rechazo: el técnico puede corregir su perfil y reenviarlo (CU-17).  **A2** Suspender un técnico verificado (por ejemplo, tras una decisión de CU-16): deja de aparecer en OficiosYa. |
| **Excepciones** | **E1** Documentos insuficientes o ilegibles: el administrador rechaza con el motivo.  **E2** El perfil cambió mientras se revisaba: el sistema pide revisar de nuevo. |
| **Postcondiciones** | El estado de verificación queda actualizado, notificado y registrado en auditoría. |
| **Reglas de negocio** | No hay verificación automática contra bases oficiales en la v1.0. La verificación queda en la auditoría (ver observación O-03). |
| **Relaciones** | Revisa lo registrado en CU-17. Habilita la aparición en CU-19 y la movilización en CU-43. |
| **Criterios de aceptación** | Un administrador verifica a un técnico y el cambio queda en la auditoría; el técnico aparece con la insignia «Verificado». |
