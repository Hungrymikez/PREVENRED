### CU-26 · Consultar indicadores psicosociales

| **Módulo · Prioridad** | M08 · Mente Resiliente · Prioridad Alta · Etapa 2 |
| --- | --- |
| **Actor primario** | Administrador |
| **Actores secundarios** | — |
| **Requisitos** | RF-17, RN-03, RNF-04 |
| **Descripción** | Permite ver los indicadores de bienestar agregados por zona, aplicando umbrales mínimos de población para evitar la reidentificación. |
| **Precondiciones** | El administrador tiene sesión vigente. Existen resultados agregados disponibles (CU-25). |
| **Disparador** | El administrador abre la sección «Bienestar (agregado)» del dashboard. |
| **Flujo principal** | **1.** El administrador selecciona el periodo y la zona.  **2.** El sistema recupera los indicadores agregados.  **3.** El sistema aplica el umbral mínimo de población y omite las zonas que no lo alcanzan.  **4.** El sistema muestra los indicadores, con modelo, versión y fecha de procesamiento.  **5.** El administrador puede ver los indicadores en el mapa mediante la capa «Bienestar por barrio». |
| **Flujos alternativos** | **A1** Una zona no alcanza el umbral: el sistema muestra «datos insuficientes» sin cifras.  **A2** Modo Emergencia: los indicadores sirven para priorizar el apoyo psicosocial. |
| **Excepciones** | **E1** No hay resultados en el periodo: el sistema lo informa.  **E2** El modelo no tiene validación vigente: el sistema advierte que los resultados no están disponibles. |
| **Postcondiciones** | El administrador conoce las necesidades de bienestar por zona sin acceder a datos individuales. |
| **Reglas de negocio** | No se muestran indicadores de barrios con población menor al umbral definido. El umbral lo define la autoridad (ver observación O-16). |
| **Relaciones** | Consume los resultados de CU-25. Alimenta la capa de bienestar de CU-40. |
| **Criterios de aceptación** | El dashboard muestra el indicador de un barrio solo si supera el umbral mínimo. |
