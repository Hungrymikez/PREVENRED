### CU-31 · Solicitar ayuda

| **Módulo · Prioridad** | M09 · Reporte de Incidentes y Solicitudes de Ayuda · Prioridad Crítica · Etapa 3 |
| --- | --- |
| **Actor primario** | Ciudadano |
| **Actores secundarios** | — |
| **Requisitos** | RF-27, RNF-01, RNF-08, RNF-10 |
| **Descripción** | Permite registrar una necesidad durante la emergencia (agua, refugio, herramientas, apoyo emocional u otra). La necesidad alimenta el banco de ayudas y el matching. |
| **Precondiciones** | El Modo Emergencia está activo. El usuario tiene sesión vigente. |
| **Disparador** | El usuario pulsa «Pedir ayuda» en la pantalla de emergencia. |
| **Flujo principal** | **1.** El usuario elige el tipo de necesidad.  **2.** El usuario indica cantidad o número de personas cuando aplica.  **3.** El sistema toma la ubicación del dispositivo y permite corregirla (ver observación O-05).  **4.** El usuario envía la solicitud.  **5.** El sistema genera un identificador de caso y registra la necesidad en estado «Reportado».  **6.** El sistema deja la necesidad disponible para el matching (CU-42) y confirma al usuario. |
| **Flujos alternativos** | **A1** Sin conectividad: la solicitud se guarda localmente y se envía al reconectar (ver observación O-02).  **A2** Necesidad de apoyo emocional: el sistema ofrece el acceso a CU-27. |
| **Excepciones** | **E1** Faltan datos mínimos para ubicar la necesidad: el sistema pide completarlos.  **E2** Falla el envío: la solicitud se conserva para reintento. |
| **Postcondiciones** | Existe una necesidad registrada con identificador, tipo, cantidad y ubicación. |
| **Reglas de negocio** | Debe completarse en máximo 3 interacciones principales (RNF-10). La necesidad nace de la solicitud ciudadana. |
| **Relaciones** | Alimenta CU-42. El ciudadano la consulta en CU-32. |
| **Criterios de aceptación** | Un ciudadano pide ayuda y la necesidad queda registrada y disponible para el matching. |
