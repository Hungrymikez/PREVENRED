### CU-37 · Sincronizar información sin conexión

| **Módulo · Prioridad** | M05 · Sincronización y Operación Offline · Prioridad Crítica · Etapa 3 |
| --- | --- |
| **Actor primario** | Sistema (para Inspector, Ciudadano y Técnico / Voluntario) |
| **Actores secundarios** | — |
| **Requisitos** | RNF-08, RNF-05, RNF-13 |
| **Descripción** | Guarda localmente y de forma cifrada lo capturado sin red y lo sincroniza automáticamente al recuperar la conexión, sin pérdida ni duplicados. |
| **Precondiciones** | El Modo Emergencia está activo. El usuario capturó información sin conectividad (censo, inspección, reportes u otros flujos de campo). |
| **Disparador** | El dispositivo no tiene red al guardar, o recupera la red con elementos pendientes. |
| **Flujo principal** | **1.** El sistema indica «Sin conexión» y guarda la captura en almacenamiento local cifrado.  **2.** El sistema asigna a cada operación un identificador único y una marca de tiempo.  **3.** El sistema muestra los elementos pendientes de envío.  **4.** Al detectar conectividad, el sistema inicia la sincronización automática en orden.  **5.** El sistema envía cada operación al servidor.  **6.** El servidor valida cada operación y detecta duplicados mediante su identificador.  **7.** El servidor confirma; el sistema marca la operación como sincronizada y elimina la copia local.  **8.** El sistema actualiza el indicador de pendientes y registra el resultado. |
| **Flujos alternativos** | **A1** Conflicto con una versión más reciente del servidor: el sistema aplica la regla de resolución definida en el diseño y avisa al usuario (ver observación O-16).  **A2** Conectividad intermitente: el sistema reintenta de forma automática hasta completar la sincronización.  **A3** Ampliación a reportes, solicitudes y confirmaciones: el mismo mecanismo se aplica a CU-29, CU-30 y CU-31 (ver observación O-02). |
| **Excepciones** | **E1** El servidor rechaza una operación (datos inválidos o catálogo desactualizado): queda marcada con error y el usuario puede corregirla sin perder los datos.  **E2** El dispositivo no tiene espacio de almacenamiento: el sistema lo advierte antes de guardar.  **E3** La sesión venció durante la sincronización: el sistema pide autenticarse de nuevo y conserva la cola. |
| **Postcondiciones** | La información capturada sin red queda en el servidor, sin pérdida ni duplicados. Los datos locales sincronizados se eliminan del dispositivo. |
| **Reglas de negocio** | Una operación creada sin red se envía una sola vez, aunque la sincronización se reintente. Los datos locales se cifran y se eliminan tras sincronizar. Alcance de la v1.0: solo funciones de campo críticas; SegundaVida, OficiosYa y Mente Resiliente no operan sin conexión. |
| **Relaciones** | «extend» de CU-34 y CU-36 (solo sin conectividad). Soporta a CU-29, CU-30 y CU-31 (ver observación O-02). |
| **Criterios de aceptación** | Una inspección creada sin red queda en el dispositivo y se sincroniza después, sin pérdida ni duplicados. |
