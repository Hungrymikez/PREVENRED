### CU-43 · Gestionar bolsa de voluntariado

| **Módulo · Prioridad** | M13 · Voluntariado · Prioridad Alta · Etapa 3 |
| --- | --- |
| **Actor primario** | Administrador |
| **Actores secundarios** | — |
| **Requisitos** | RF-28, RF-10, RF-05 |
| **Descripción** | Permite activar la bolsa de voluntarios y profesionales y asignarlos a casos según habilidades, disponibilidad, ubicación, certificaciones y autorización. |
| **Precondiciones** | El Modo Emergencia está activo. Existen voluntarios o técnicos registrados (CU-17 y CU-44). |
| **Disparador** | El administrador abre «Voluntariado» en el dashboard. |
| **Flujo principal** | **1.** El administrador activa la bolsa de voluntariado al iniciar la emergencia.  **2.** El sistema lista los voluntarios con habilidades, disponibilidad, ubicación aproximada, certificaciones y estado.  **3.** El administrador filtra según el caso: especialidad, cercanía y autorización.  **4.** El administrador convoca a voluntarios o selecciona a uno directamente.  **5.** El sistema valida que el rol y la autorización estén vigentes y que esté disponible.  **6.** El administrador confirma la asignación.  **7.** El sistema pasa al voluntario a «Asignado», lo notifica y registra la asignación en auditoría (CU-05).  **8.** El sistema actualiza el contador de voluntarios movilizados.  **9.** Al resolverse el caso, el sistema cierra la asignación y libera al voluntario. |
| **Flujos alternativos** | **A1** Convocatoria por especialidad o zona: los voluntarios responden mediante CU-44.  **A2** Reasignación: el administrador cambia al voluntario y el sistema notifica a ambos.  **A3** Al terminar la emergencia, el administrador desactiva la bolsa. |
| **Excepciones** | **E1** El voluntario no tiene autorización vigente: el sistema impide la asignación.  **E2** El voluntario declina: el sistema libera el cupo y pide elegir otro.  **E3** Falla el registro de auditoría: la asignación no se confirma. |
| **Postcondiciones** | El voluntario queda asignado al caso y notificado; la asignación está auditada. |
| **Reglas de negocio** | Solo se asigna a personas con rol y autorización vigentes. Los planes pagos de OficiosYa no influyen en la selección. La ubicación del voluntario se comparte únicamente mientras esté asignado. |
| **Relaciones** | «include» CU-05. Usa perfiles de CU-17 y postulaciones de CU-44. Notifica por CU-06. |
| **Criterios de aceptación** | El coordinador asigna a un voluntario a un caso según habilidad y cercanía, y el cambio queda registrado y notificado. |
