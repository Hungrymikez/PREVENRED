### CU-06 · Emitir notificaciones de crisis

| **Módulo · Prioridad** | M03 · Notificaciones y Alertas · Prioridad Crítica · Etapa 3 |
| --- | --- |
| **Actor primario** | Sistema (disparado por CU-04) |
| **Actores secundarios** | Servicio Push/SMS |
| **Requisitos** | RF-04, RF-24, RNF-01, RNF-07, RNF-14 |
| **Descripción** | Al activarse una emergencia, envía notificaciones Push y, cuando corresponda, SMS a las zonas y poblaciones definidas por la autoridad, respetando preferencias y excepciones legales. También sirve a los avisos de cambio de estado de casos y de movilización. |
| **Precondiciones** | El administrador activó el Modo Emergencia indicando zonas o poblaciones (CU-04). Hay plantillas de mensaje y un proveedor de mensajería configurados. |
| **Disparador** | CU-04 activa el Modo Emergencia. |
| **Flujo principal** | **1.** El sistema recibe el tipo de evento y las zonas o poblaciones a notificar.  **2.** El sistema determina los destinatarios por zona y aplica sus preferencias de notificación y las excepciones legales.  **3.** El sistema arma el mensaje a partir de la plantilla (tipo de evento e instrucciones de la autoridad).  **4.** El sistema encola los envíos Push al proveedor.  **5.** Para quienes no tienen la aplicación activa, o cuando el Push no es suficiente, el sistema encola SMS.  **6.** El proveedor entrega y devuelve el estado de cada envío.  **7.** El sistema registra por envío: estado, reintentos, fecha y hora, zona y proveedor.  **8.** El sistema reintenta los envíos fallidos según la política definida y deja el resultado consultable para el administrador. |
| **Flujos alternativos** | **A1** Avisos de casos y movilizaciones: CU-39, CU-42 y CU-43 usan el mismo mecanismo para avisar al ciudadano, voluntario o técnico de un cambio de estado o una asignación. |
| **Excepciones** | **E1** El proveedor no responde: el sistema reintenta, usa el canal alterno y genera una alerta operativa.  **E2** Se alcanza un límite del proveedor: el sistema encola y degrada de forma controlada, priorizando las zonas indicadas.  **E3** Destinatario sin contacto válido: se registra como no entregado. |
| **Postcondiciones** | Los usuarios de las zonas seleccionadas fueron notificados o quedó registrado el motivo de no entrega. |
| **Reglas de negocio** | Las comunicaciones de emergencia se limitan a las zonas y poblaciones definidas por la autoridad. Los envíos quedan trazados y sujetos a los límites del proveedor. No se envían notificaciones comerciales ni de marketing. |
| **Relaciones** | «extend» de CU-04 (solo al activar el Modo Emergencia). Los destinatarios la reciben en CU-07. |
| **Criterios de aceptación** | Al activar una emergencia simulada, los usuarios de las zonas seleccionadas reciben el aviso y el envío queda registrado con fecha, zona y resultado. |
