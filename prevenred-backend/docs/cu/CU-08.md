### CU-08 · Gestionar usuarios y roles

| **Módulo · Prioridad** | M01 · Acceso, Usuarios y Roles · Prioridad Crítica · Etapa 1 |
| --- | --- |
| **Actor primario** | Administrador |
| **Actores secundarios** | — |
| **Requisitos** | RF-03, RN-05, RN-07, RNF-06 |
| **Descripción** | Permite administrar las cuentas: crear cuentas de Inspector y de Administrador, editar datos, asignar o cambiar roles y suspender o reactivar usuarios, aplicando mínimo privilegio. |
| **Precondiciones** | El administrador tiene sesión vigente, autenticada con segundo factor (CU-02 y CU-03). Tiene permiso para administrar usuarios. |
| **Disparador** | El administrador abre la pantalla «Usuarios y roles» del dashboard. |
| **Flujo principal** | **1.** El sistema lista los usuarios con rol y estado, con búsqueda y filtros.  **2.** El administrador selecciona una acción: crear cuenta, editar datos, asignar o cambiar rol, suspender o reactivar.  **3.** El sistema muestra el formulario o la confirmación correspondiente.  **4.** El administrador completa los datos o confirma.  **5.** El sistema valida las reglas de mínimo privilegio y que la acción esté permitida.  **6.** El sistema aplica el cambio.  **7.** El sistema registra el evento en auditoría (CU-05).  **8.** El sistema notifica al usuario afectado cuando se modifica su rol o estado. |
| **Flujos alternativos** | **A1** Crear cuenta de Inspector o Administrador: el sistema genera las credenciales iniciales y obliga a cambiarlas en el primer acceso.  **A2** Suspender un usuario: se bloquea el acceso y las sesiones activas se revocan. |
| **Excepciones** | **E1** El cambio dejaría la plataforma sin administradores o elevaría privilegios sin autorización: el sistema lo impide.  **E2** El usuario ya no existe o fue modificado por otro administrador: el sistema informa y recarga los datos.  **E3** Falla el registro de auditoría: el cambio no se aplica. |
| **Postcondiciones** | La cuenta y el rol quedan actualizados. El cambio queda en la auditoría. |
| **Reglas de negocio** | RN-07: mínimo privilegio y MFA en permisos de administración. RN-05: acceso restringido a datos personales; solo se muestran los necesarios para administrar. |
| **Relaciones** | «include» CU-05 (auditoría). |
| **Criterios de aceptación** | Un administrador crea una cuenta de Inspector y asigna su rol; el cambio queda en la auditoría y el usuario solo accede a funciones de ese rol. |
